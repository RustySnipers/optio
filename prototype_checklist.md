# EXECUTION: PROTOTYPE COMPLETION CHECKLIST
The following checklist prioritizes Functional Viability and Security Essentials over aesthetic polish.

## PHASE 1: THE NERVOUS SYSTEM (Agent-Hub Communication)
The prototype is dead if the brain (Hub) cannot talk to the limbs (Agents).

### ✅ Establish the mTLS Handshake

- [x] Action: Verify optio-hub spins up a secure gRPC/HTTPs listener using certificates generated by scripts/generate-test-certs.sh.
- [x] Action: Hardcode the Hub's development IP into the optio-agent config for testing.
- [x] Validation: Agent must successfully connect and receive a 401 Unauthorized (if no cert) or 200 OK (with cert).

### ✅ Implement the "Heartbeat" Loop

- [x] Action: In optio-agent/src/main.rs, implement an infinite async loop (Tokio) that sends a HeartbeatRequest (defined in optio.proto) every 30 seconds.
- [x] Data: Heartbeat must include machine_id, hostname, os_version, and agent_version.
- [x] Hub Response: Hub must reply with HeartbeatResponse containing a list of PendingCommands.

### ✅ Command Queue & Dispatch

- [x] Action: In optio-hub, implement a memory-based (or SQLite) queue that stores commands targeting specific machine_ids.
- [x] Action: Connect the Frontend "Terminal" component to push commands into this queue.
- [x] Validation: Type whoami in Hub Terminal -> Agent receives command -> Agent executes -> Agent posts result back to Hub.

## PHASE 4: SECURITY HARDENING (Alpha Requirements)
Do not ship the prototype without these baselines.

### ✅ Replay Attack Prevention

- [x] Action: Implement Nonce validation. The Agent should send a nonce with the Heartbeat; the Hub signs the response. (See optio-core/src/security/mod.rs).
  - Added `nonce` and `client_timestamp_ms` to HeartbeatRequest proto
  - Implemented `NonceValidator` in security/mod.rs
  - Hub validates nonces in grpc.rs
- [x] Validation: Replaying a captured Heartbeat packet must result in a server rejection.

### ✅ PowerShell Constrained Language Mode

- [x] Action: The Agent's command executor (terminal.rs) must explicitly check if it's running in Constrained Language Mode (CLM) and downgrade functionality gracefully if necessary, or attempt to bypass if authorized (for the prototype, just logging the mode is sufficient).
